# dp-sort-host, dp-sort-child — User Manual

| :------------ | :----------------------------------------------------------------- |
| Products      | `dp-sort-host` 1.0.0, `dp-sort-child` 1.0.0                        |
| Project       | `34-parallel-sort` — Distributed Parallel Sorting & Stream Merging |
| Applies to    | Linux, macOS, Windows                                              |

## NAME

**dp-sort-host** — sort integers with a concurrent worker and merge the two sorted halves

**dp-sort-child** — serve one sort request of the worker protocol

## SYNOPSIS

```text
dp-sort-host [-t | --trace] [FILE]
dp-sort-host [-t | --trace] (-r COUNT | --random=COUNT) [--seed=SEED]
dp-sort-child [FILE]
dp-sort-host --help | --version
dp-sort-child --help | --version
```

## DESCRIPTION

`dp-sort-host` reads integers from _FILE_, or from standard input when there is no _FILE_ or
_FILE_ is `-`, and writes them sorted in non-decreasing order, one per line. It does the work
the way a small parallel computer would:

1. It keeps the first half of the numbers (rounded down) and sends the rest to a **worker**
   that runs at the same time.
2. Both sort their half with selection sort, concurrently.
3. The host merges its sorted half with the sorted numbers the worker sends back, always
   writing the smaller of the two next numbers, and the host's number first when they are
   equal.

Up to 100000 integers from −9223372036854775808 to 9223372036854775807 are accepted, separated
by any mix of spaces, tabs, and line breaks; signs and leading zeros are allowed (`+5` and
`007` are written as `5` and `7`). Files with Windows (CRLF) line endings read the same as any
other, and Ctrl-Z bytes at the very end of the input are ignored. The whole input is checked
before sorting starts, so an invalid number produces an error message and no output.

With `--random`, `dp-sort-host` sorts _COUNT_ pseudo-random integers from 0 to 32767 instead
of reading input, generated by the curriculum's portable generator from _SEED_.

### The worker protocol

Host and worker exchange **messages**: lines holding one integer each, in plain decimal,
ending in a line feed. The host sends a **request** — the number of values, then the values —
and the worker sends back a **reply** — the same values, sorted, one per line — and nothing
else.

`dp-sort-child` is the worker as a standalone tool: it reads one request from _FILE_ or
standard input, writes the reply to standard output, and exits. It reads its input as
whitespace-separated numbers, so the request may be typed by hand, several numbers to a line.
It stops reading as soon as the last value is complete and ignores anything that follows. The
size must be from 0 to 100000.

`dp-sort-host` may run its worker as a thread, as a separate process, or as `dp-sort-child`
itself; the results and the trace are the same in every case.

### The trace

With `--trace`, `dp-sort-host` writes to standard error one line for each message and each
step of the merge:

```text
host -> child: 5         the host sends a request message
child -> host: -12       the host receives a reply value from the worker
merge: -12 from child    the merge writes a value from the worker's half
merge: -5 from host      the merge writes a value from the host's half
```

The host sends the whole request first. During the merge it receives a reply value only when
it needs one: one at the start, and one after each value it writes from the worker's half.
The trace depends only on the numbers, never on timing, so it is the same on every run and
every computer.

## OPTIONS

### dp-sort-host

**`-t`, `--trace`**
: Write the trace described above to standard error.

**`-r COUNT`, `--random=COUNT`**
: Sort _COUNT_ (0 to 100000) pseudo-random integers from 0 to 32767 instead of reading input.
No _FILE_ may be given.

**`--seed=SEED`**
: Start the random-number generator from _SEED_, a whole number from 0 to 4294967295 (digits
only). The default is 1. Without `--random` it has no effect.

### Both tools

**`--help`**
: Display the tool's help text below and exit with status 0.

**`--version`**
: Display the version line and exit with status 0.

### Option syntax

Both tools follow the curriculum's common conventions (`shared/CLI-CONVENTIONS.md`):

- An option's value can be attached or separate: `-r10`, `-r 10`, `--random=10`, and
  `--random 10` are equivalent.
- Long options must be spelled out in full; `--rand` is not accepted.
- Options and the file name can be given in any order: `dp-sort-host data.txt -t` works.
- If an option is given more than once, the last one wins.
- `--` ends option processing, so `dp-sort-host -- -t` reads a file named `-t`.
- `--help` and `--version` take effect as soon as they are reached while reading the arguments
  from left to right, unless an earlier argument was invalid.

## EXIT STATUS

| Status | Meaning                                                                                   |
| :----- | :---------------------------------------------------------------------------------------- |
| 0      | Success: the numbers were sorted (an empty input is fine), or help or version was printed |
| 1      | The input could not be read, it contained invalid data, or the worker failed              |
| 2      | Usage error: an invalid option or value, or an operand too many                           |

## DIAGNOSTICS

Problems with the data name the input (`-` for standard input) and the line number. Nothing is
written to standard output, and the exit status is 1:

```text
$ dp-sort-host bad.txt
dp-sort-host: bad.txt:3: invalid integer '4.5'
```

| Message                        | Cause                                                                                 | Fix                                                             |
| :----------------------------- | :------------------------------------------------------------------------------------ | :-------------------------------------------------------------- |
| `S:L: invalid integer 'K'`     | Entry _K_ on line _L_ is not a whole number, or is outside the 64-bit range           | Write the number in digits only, without separators or decimals |
| `S:L: too many values`         | `dp-sort-host`: the input holds more than 100000 numbers; line _L_ holds the 100001st | Split the input                                                 |
| `S:L: value out of range 'K'`  | `dp-sort-child`: the size _K_ is negative or above 100000                             | Give a size from 0 to 100000                                    |
| `S:L: unexpected end of input` | `dp-sort-child`: the input ended before the size or before the last value             | Supply as many values as the size says                          |
| `worker failed`                | `dp-sort-host`: the worker could not be started or did not answer correctly           | Check the installation (a defective implementation)             |
| `F: No such file or directory` | _F_ does not exist                                                                    | Check the spelling and the current directory                    |
| `F: Permission denied`         | You may not read _F_                                                                  | Check the file's permissions                                    |
| `F: Is a directory`            | _F_ is a directory                                                                    | Name a file instead                                             |
| `F: Not a directory`           | Part of the path _F_ is a file, not a directory                                       | Correct the path                                                |
| `F: Input/output error`        | Any other read failure                                                                | Check the device or file system                                 |
| `write error`                  | The output could not be written (for example, the disk is full)                       | Free space or redirect the output elsewhere                     |

Usage errors are written to standard error as two lines; nothing is read and nothing is
written to standard output:

```text
$ dp-sort-host -r 5 data.txt
dp-sort-host: extra operand 'data.txt'
Try 'dp-sort-host --help' for more information.
```

| Message                                      | Cause                                                   | Fix                               |
| :------------------------------------------- | :------------------------------------------------------ | :-------------------------------- |
| `invalid option -- 'x'`                      | Unknown short option `-x`                               | Use `-t` or `-r` (`dp-sort-host`) |
| `unrecognized option '--xyz'`                | Unknown or abbreviated long option                      | Spell the option in full          |
| `option requires an argument -- 'r'`         | `-r` given without a value                              | Supply a count                    |
| `option '--random' requires an argument`     | `--random` or `--seed` given without a value            | Supply a value                    |
| `option '--trace' doesn't allow an argument` | A value was given with `=` to an option that takes none | Remove the `=…`                   |
| `invalid argument 'C' for '--random'`        | _C_ is not a whole number from 0 to 100000              | Use digits only, within the range |
| `invalid argument 'S' for '--seed'`          | _S_ is not a whole number from 0 to 4294967295          | Use digits only, within the range |
| `extra operand 'F'`                          | More than one file, or a file together with `--random`  | Name one file, or drop it         |

## EXAMPLES

Sort a file:

```text
$ dp-sort-host data.txt
-12
-5
0
4
8
17
17
23
42
99
```

Watch a small sort (the data set 3, 5, 5, 5, 1, 5; the trace is on standard error):

```text
$ echo 3 5 5 5 1 5 | dp-sort-host --trace 2>&1 >/dev/null
host -> child: 3
host -> child: 5
host -> child: 1
host -> child: 5
child -> host: 1
merge: 1 from child
child -> host: 5
merge: 3 from host
merge: 5 from host
merge: 5 from host
merge: 5 from child
child -> host: 5
merge: 5 from child
```

Talk to the worker directly:

```text
$ printf '3\n9\n-1\n4\n' | dp-sort-child
-1
4
9
```

Sort ten random numbers:

```text
$ dp-sort-host --random=10
4086
5627
5758
7419
10113
16212
16838
17515
23010
31051
```

## HELP OUTPUT

`dp-sort-host --help` and `dp-sort-child --help` print exactly the following texts (every line
ends in LF). The help texts are part of the specification (CONV-23).

`dp-sort-host --help`:

```text
Usage: dp-sort-host [OPTION]... [FILE]
Sort integers with a concurrent worker and merge the two sorted halves.

With no FILE, or when FILE is -, read standard input.  Up to 100000 integers,
separated by whitespace, are read.  The first half is sorted here and the rest
by a worker running at the same time; the merged result is written one
integer per line.

Options:
  -r, --random=COUNT   sort COUNT pseudo-random integers 0-32767 (0-100000)
                         instead of reading input
      --seed=SEED      seed the pseudo-random generator (0-4294967295,
                         default 1)
  -t, --trace          write the messages exchanged with the worker and each
                         merge step to standard error
      --help           display this help and exit
      --version        output version information and exit
```

`dp-sort-child --help`:

```text
Usage: dp-sort-child [OPTION]... [FILE]
Serve one sort request: read a count and that many integers, and write them
sorted in non-decreasing order, one per line.

With no FILE, or when FILE is -, read standard input.  The count (0-100000)
and the integers are separated by whitespace.  Input after the last integer
is not read.  This is the worker of dp-sort-host.

Options:
      --help      display this help and exit
      --version   output version information and exit
```

## ENVIRONMENT

Both tools ignore all environment variables, including locale settings (`LANG`, `LC_ALL`).
Numbers are always read and written with ASCII digits and no digit grouping.

## PLATFORM NOTES

- **All platforms:** the output and the trace are the same whatever the number of processor
  cores and however the operating system schedules the host and the worker. On a machine with
  several cores the two halves are really sorted at the same time.
- **Windows:** data files are read as raw bytes: CRLF line endings are accepted, and Ctrl-Z
  bytes at the very end of a file are ignored, but a Ctrl-Z byte in the middle of a file is an
  error. Output uses LF line endings, not CRLF. When you type a request for `dp-sort-child` at
  a console, it answers as soon as the last value is followed by Enter.
- **macOS / Linux:** end keyboard input for `dp-sort-host` with Ctrl-D at the start of a line.

## INSTALLATION

From an implementation's project directory (see the curriculum `README.md`):

```sh
make all          # build dp-sort-host and dp-sort-child
make install      # install both into ~/.local/bin (override with PREFIX=/some/prefix)
make uninstall    # remove them again
```

Make sure the install directory is on your `PATH`. Install both tools into the same directory:
an implementation may run `dp-sort-child` from the directory that holds `dp-sort-host`.

# Project 23 — Recursion vs. Iteration Comparative Suite (`dp-fact`, `dp-tower`, `dp-walk-r`, `dp-walk-nr`)

> Compute factorials, solve the Tower of Hanoi, and count robot walks with recursive
> algorithms that are exact up to the limits of 64-bit arithmetic — and answer the same walk
> question twice, by tree recursion and by iteration, with byte-identical output but very
> different run times, on Linux, macOS, and Windows.

## Purpose

Project 23 is adapted from §4.8 of Johnsonbaugh & Kalin, *Applications Programming in ANSI C*,
the section that introduces recursion. Its four programs become four tools. `dp-fact` computes
*n*! by the recursive definition. `dp-tower` prints the 2ⁿ − 1 moves of the Tower of Hanoi,
generated by the classic recursive procedure. `dp-walk-r` and `dp-walk-nr` count the ways a
robot can walk *d* meters in steps of 1 and 2 meters, W(*d*) = W(*d* − 1) + W(*d* − 2): the
first by plain tree recursion, which recomputes the same sub-problems an exponential number of
times, the second by a loop that keeps two numbers. The black-box tests prove that the two walk
tools agree; design review and measurement prove that they differ. The textbook computed in C
types whose width varies between platforms and overflowed silently; here every tool has an
explicit limit chosen so that every result is exact in 64 bits on every platform, and a number
beyond it is refused with a precise diagnostic.

## Operational scope

| In scope | Out of scope |
| :-- | :-- |
| Numbers as whitespace-separated integer tokens until end of input (CONV-32, CONV-33) | Arbitrary-precision results, real numbers |
| `dp-fact`: *n*! for 0 ≤ *n* ≤ 20, by recursion | Gamma function, factorials beyond 20! |
| `dp-tower`: the 2ⁿ − 1 moves for up to 20 disks, pegs A → B with spare C; `There's nothing to move!` for *n* < 1 | Other numbers of pegs, other start and end pegs, graphics |
| `dp-walk-r` (1 ≤ *d* ≤ 45, tree recursion) and `dp-walk-nr` (1 ≤ *d* ≤ 91, iteration), identical answers | Other step sizes; memoized or closed-form variants |
| Standard input or one `FILE` operand (`-` is standard input); one answer per number, flushed at once | Several input files, writing files |
| Optional prompts on standard error (`-p`, `--prompt`, CONV-36) | Prompts on standard output |
| CRLF input and a trailing Ctrl-Z end-of-file marker (CONV-37) | Other legacy encodings |
| Data diagnostics with line numbers (CONV-34), CONV-16 file errors | Recovering after an invalid number |
| Run-time requirements checked by measurement | Timings in the output |
| `--help`, `--version`, CONV-13 usage errors for all four tools | Configuration files, environment variables |

## Learning objectives

1. Formulate base cases and recursive steps, and implement a recursive function (*n*!) and a
   recursive procedure with several parameters (the Tower of Hanoi) directly from their
   definitions (FR-06, FR-07, NFR-05).
2. Measure the cost of naive tree recursion, relate it to the number of calls,
   C(*d*) = 2·W(*d* − 1) − 1, and convert the recurrence into an O(*d*)-time, O(1)-space loop
   with identical results (FR-11, NFR-03, NFR-05).
3. Choose input limits from the range of a 64-bit integer and the size of the output, and test
   both sides of every limit (FR-02, FR-05).
4. Write exponentially long output as it is generated, in constant memory, and stop quietly on
   a broken pipe (FR-03, NFR-03, NFR-04).
5. Avoid platform-dependent integer widths and stack sizes, so that recursive code gives the
   same exact answers on Linux, macOS, and Windows (NFR-02).
6. Share one input loop and one command-line parser among four tools (NFR-05).

## Quick start

```sh
make all            # build dp-fact, dp-tower, dp-walk-r, and dp-walk-nr into BIN_DIR
make test           # unit tests + 10 public black-box tests
make lint format    # static analysis and formatting
make test-hidden    # hidden suite (CI does this on Linux, macOS, and Windows)
```

## Acceptance

The project is complete when `make test` and `make test-hidden` pass on all three operating
systems in CI, `make lint` is clean, and every RTM row is *Verified*.
